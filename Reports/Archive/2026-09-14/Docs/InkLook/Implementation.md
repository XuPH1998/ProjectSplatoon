# 粉蓝墨水修复 · 版本 4

默认 32×64 米多层训练场已采用连续墨量、按米表面细节、粉蓝队主题和独立显示扩边。粉队保留参考浮点颜色 `RGBA(0.9433962, 0.27945885, 0.47586557, 1)`；蓝队采用 `#7DE3E8`。颜色入口为 `PrototypeArena.TeamColor`，编号仍为 1 / 2。

## 上次移植的差距与本次修复

上次绘制器将低于阈值的笔刷抛弃，高于阈值的像素写成全量颜色，参考材质所依赖的连续 Alpha 因而消失。立方体被拉伸后仍使用相同 UV 和物体空间闪点，长墙的六面图集精度也不足。上次验证主要覆盖写入、恢复和同步，未完成同条件视觉对照。

本次保留参考的平滑笔刷、噪声轮廓与高度法线关系，改为独立的 URP `InkSurface` 着色器。表面坐标从世界位置投影，以 `0.034424 UV/米` 起步；底面、坡道与墙面不再随模型缩放改变纹理频率。长面拆为图集块，保持碰撞体、稳定表面 ID、场地几何和阵营出生关系。

## 状态、玩法与同步

- 原始 RGBA32 状态：R=粉墨量、G=蓝墨量、B=主导队伍字节 1/2、A=饱和总墨量。喷涂平滑增加己方墨量并衰减敌方，平手保留先前归属；每次写入统一按字节量化。
- 显示纹理由原始状态生成，按主导队色与连续 Alpha 显示。图集边缘复制完整邻居状态，扩边结果不回写累积纹理；每帧仅刷新脏表面一次。
- CPU 每个 0.125 米格保存双队累积状态，以相同笔刷、稳定空间噪声和阈值计算覆盖。比分与潜墨使用这份归属，坡道按斜面实际面积计分，桥上桥下独立。
- 轮廓判定为 `alpha * (1 + 0.5 * noise) >= threshold`，阈值 0.5 时等价于参考图的 `step(1-alpha, alpha+alpha*noise)`。高度为 `0.3 + alpha * bumpNoise²`。
- 检查点保存各格归属及 RGBA 累积状态、各表面原始纹理；恢复后重新扩边。`PaintStamp` 网络字段和顺序不变，快照格式与内容签名为 4 / `ink-lan-v4`，地图几何布局版本继续为 3。
- Luban 新增 `paintWorldUvScale`、`paintShapeNoiseScale`；覆盖阈值与笔刷参数一并参与连接签名。源 `TbGlobal.xlsx` 已重新生成 C# / JSON；没有手改生成数据。

## 美术与资源

队色贯通表面、飞行墨流、命中和潜墨粒子、角色队色部件、HUD/比分/菜单、出生区与分区标识。`Orange` / `OrangeArea` 的运行时语义改为 `Pink` / `PinkArea`；材质重命名保留 GUID，中文字体测试包含“粉”。历史移植验证文档保留其原始记录。

显示材质的两队颜色声明为 `Color` 属性，由 Unity 按颜色空间转换一次，避免粉色变浅和薄荷蓝漂白。高光随机方向、表面法线和视线统一在世界空间。细碎闪点在高光计算后进行插值，并按屏幕覆盖范围淡出过远的细节，避免先平滑随机法线导致高光消失。

训练场使用明亮的参考网格底材、提亮混凝土墙、暖色主光、参考 `Sky_8` 天空与已烘焙的天空反射 Cubemap（不依赖 PC 已关闭的实时反射开关）。独立战斗 Volume 使用 Neutral 色调映射与 0.08 Bloom。飞行墨流延续每发 2 个视觉粒子、0.17 米粒径、移动时每米补充 10 个视觉粒子、三次模糊和深度遮挡；这些参数不改变权威弹道、伤害或耗墨。

墨水纹理常驻 **91.49 MiB**；包含最坏检查点副本和共享中间纹理的峰值预算 **118.68 MiB**，低于 128 MiB。该预算针对墨水状态/显示/图集/中间纹理，不是整个游戏或屏幕特效的总显存。

## Windows 720p 四人持续喷涂

硬件为 i7-11700K / RTX 3060，D3D11；同机 1 个图形房主 + 3 个无图形客户端，开发构建，每秒约 160 次权威喷涂。预热 5 秒后测量 40 秒，图形端每帧显式提交 1280×720 渲染，性能采样期间不截屏。程序帧率上限为 120，结果不表示无上限峰值性能。

| --- | --- |
| 样本 | 4800 帧 |
| P50 / P95 / P99 | 8.334 / **8.335** / 8.346 ms |
| 最大帧间隔 | 8.723 ms |
| 托管分配总量 / 最大单帧 | 66,835,395 / 4,197,130 字节 |

检查点 CPU 读回和打包仍产生约 4 MiB 的瞬时托管分配；当前采样未出现帧时尖峰，但这不是零分配实现。报告的 118.68 MiB 上限是墨水纹理和 GPU 检查点副本的预算，CPU 快照字节数组、其他场景资源和屏幕特效显存另计。数据见 `Logs/InkLook/ink-performance-*.json`。

## 复验入口

1. 从 `Assets/Scenes/Main/Boot.unity` 进入；默认载入已保存的 TrainingGround。
2. `Splatoon.Editor.InkLookValidation.Run` 运行 GPU 检查并生成 1080p 参考图；需图形设备，不能带 `-nographics`。
3. `Splatoon.Editor.PrototypeBuilder.BuildWindows` 构建当前内容；无需再安装或生成旧地图。
4. 开发版显式使用 `-lanSmokeHost` / `-lanSmokeClient`，配合 `-inkSmokeCase surfaces|map|observer|inkperf`。正常游戏不传诊断参数。
5. `inkperf` 只在开发构建启用，四人到齐后补充测试用墨水，预热 5 秒，采样 40 秒；图形端每帧显式渲染 1280×720 场景，避免隐藏窗口跳过背缓冲造成虚高帧率。

同机自动化不能代替两台实体电脑局域网、人工键鼠操作和长期对战平衡验收。
