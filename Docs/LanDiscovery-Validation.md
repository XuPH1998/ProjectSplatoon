## 证据与复跑

- 编辑器测试结果：`Logs/room-discovery-editor.xml`。
- Play Mode 检查结果：`Logs/room-lobby-playmode.txt`，成功结果为 `passed=True`。
- 截图：`Logs/room-lobby-list.png`、`Logs/room-lobby-scroll.png`、`Logs/room-lobby-returned.png`。列表截图中的 10 个房间是测试驱动通过真实 UDP 创建的测试房间，不代表 10 个外部玩家房间。
- 菜单 **喷墨对战 / 验证 / 房间发现与地图配置 EditMode** 可复跑定向测试。
- 保存并打开 Boot 场景，菜单 **喷墨对战 / 验证 / 房间列表 PlayMode** 可复跑 Windows 原生交互验证。测试使用游戏端口 19300–19309（虚拟房间信息）、19477（真实本地房主）、19478（取消连接目标），以及发现 UDP 47777；不要同时运行占用这些测试端口的其他程序。
- Play Mode 驱动会检查 Unity 位于前台后再点击，结束时退出测试 Play Mode、恢复原 Game View 尺寸与鼠标位置；不关闭用户编辑器。

源表仅发生 `Arena → Map` 工作表改名及 `RoomMode!F1` 的 `arenaId → mapId`、`F3` 的“场地 ID → 地图 ID”。地图 JSON 与旧表对应数据一致，原 JSON 及生成 C# 的 Unity GUID 随重命名保留，Addressables 地址更新为 `tbmap`。
