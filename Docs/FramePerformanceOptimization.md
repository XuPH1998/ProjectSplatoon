# 四人对局帧率优化

本轮保持武器、粒子密度、材质、模糊次数、模拟频率和网络协议不变。

## 绘墨

CPU 归属仍在 `PrototypeArena.Apply` 中立即按序更新。区域缓存变换矩阵、逆矩阵与法线；格子缓存世界位置和固定噪声系数；每笔笔刷只计算一次投影基和随机旋转。矩阵、区域原点/旋转、噪声尺度变化会使相应缓存失效。注册地图时缓存表面顺序，热路径使用数组遍历，避免逐笔创建枚举器。

GPU 的每笔绘制参数进入表面本地队列。`FlushPaint` 按原顺序在固定 Mask 与已有共享 Scratch 间交替绘制；偶数笔直接落在 Mask，奇数笔最后复制回 Mask。共享 Scratch 的 UV 空隙先清零，材质参数由每次 DrawMesh 的属性块快照隔离。保持原始逐笔量化、覆墨和纹理格式；没有合并墨量或重排同一表面的笔迹。

`LateUpdate/FlushDisplay` 在主相机前提交；读取 `Mask` 同样强制提交，因此检查点与 GPU 读回拿到当前序号的完整状态。清场和卸载丢弃队列，合法的快照恢复替换待提交状态；非法快照不会清掉待提交墨迹。Mask 对象身份不变，RT 数量和尺寸不增加。

## 飞行与合成

每发射击的随机偏转和卫星粒子速度在入池时计算，更新只遍历活跃分组。仍保留原来的稳定出生排序、粒子年龄、实际弹道与命中回收规则。拖尾保持固定顶点容量，用一个交错顶点缓冲仅上传有效范围，避免缩容时旧索引越界。

墨水合成先检查相机图层，再检查对应运行时通道的完整存活状态。枪口停火/退役残留、潜墨粒子和命中特效都参与判断；有爆炸对象或未知过滤图层时保守保留通道。编辑器参考相机继续渲染独立特效。有效通道仍使用原分辨率、三次模糊与材质。

## 验证入口

- `FrameOptimizationTests` 使用冻结的原版算法，对比 CPU 状态、GPU 纹理、粒子、拖尾和正常/异常生命周期。
- `FramePerformanceProbe` 和 `Tools/Performance/README.md` 提供正常 Player 帧采样及辅助同机矩阵。未启用采样参数时不会创建探针。
- 本轮原始证据和基线副本在 `Reports/FourPlayerPerformance/`；报告说明每次验证的实际范围，不把算法耗时、同机进程或 Editor 结果当作四台设备稳定 60 FPS 的证明。

CPU 缓存包括归属格子的位置/噪声/有效标记（约 17 字节/格，另有数组头），以及每个弹药版本约 1.125 MiB 的固定视觉参数数组。它们复用至对象释放，不增加每帧分配，也不增加墨迹 RT 内存。拖尾原生顶点缓冲仅在分组首次实际使用时创建，随后保持容量复用，闲置池槽不提前分配这些缓冲。
