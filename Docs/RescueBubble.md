# 被击倒泡泡与救援

## 行为

致命伤害进入 `PlayerLifeState.Bubble`，生命值为零但尚未计分，也不启动死亡动画或重生倒计时。泡泡中的角色保持固定待救姿态，可以转动视角并以 0.6 米/秒移动；不能使用武器、潜墨、跳跃、救援、切换英雄或换队。普通攻击不破泡。

泡泡半径由实际站立待救姿态的角色与武器网格边界决定，人物最远端至少保留 0.2 米余量。房主同步半径和中心高度；客户端不重新猜测尺寸。当前九个英雄实测半径约 1.21–1.55 米。

| 结束方式 | 结果 | 计分与涂墨 |
| --- | --- | --- |
| 队友单按 F | 原地满血满墨复活，无无敌；空中救起正常下落 | 无击杀、死亡或涂墨 |
| 敌方单按 F | 死亡动画与原有重生等待同时开始 | 击杀归原击倒者，使用原击倒者队伍颜色涂墨 |
| 10 秒到期 | 同上 | 同上 |

F 要求操作者存活、距离泡泡表面不超过 1 米且到泡泡中心无遮挡。提示选取最近的有效泡泡并高亮；输入携带目标与目标生命编号。每帧先处理全部超时，再按房主接收顺序处理 F 请求，同一泡泡仅结束一次。助攻窗口固定在击倒时计算，不因十秒待救而失效。

死亡泡泡以中心为球心、4 米为半径涂覆可达表面，受遮挡裁剪，通过现有涂墨事件/检查点同步。`PureInkBlast` 不调用任何角色或副武器物件伤害入口；敌色地面之后仍遵循游戏原有的地面资源规则。

## 配置和实现

- `Config/Luban/source/TbRoomMode.xlsx` 的八个 `bubble*` 字段控制时长、速度、重力、下落上限、回弹、交互距离、涂墨半径和包裹余量。修改源表及定义后运行 `cmd /c Config\Luban\gen_luban.bat`；生成代码/JSON 不手改。
- 玩家快照协议升级为 **34**。快照增加待救状态、截止时间、球体尺寸、结束结果及事件编号；输入增加 F 序号、目标 ID 与生命编号。旧版本无法混用。
- `PrototypePlayer.RescueBubble` 负责状态转换与房主校验；`RescueBubbleMotor` 负责与预测共用的球形扫掠、重叠修正与反弹；`RescueBubbleView` 负责透明泡泡、高亮和爆裂效果。待救角色保持零血，原有武器和资源系统不会把它作为存活目标。
- 非凸地图网格的重叠探测使用启用的触发球。禁用探测球会使首次重叠无法正确修正，而球形扫掠不会补报已嵌入的地板；已添加专门回归测试。
- 比赛结束冻结泡泡及交互，回合重置、重生和退出清理泡泡。越界继续走原有处理。击倒者离线不改变已保存的爆墨队伍，且不会把击杀转给处决者。

## 验证

2026-09-22，Unity 6000.3.9f1：

- 定向 Edit Mode：30 项通过，涵盖新状态、截止边界、尺寸余量、非凸地板初始重叠、交互资格、助攻/击杀与救援重置、完整/增量快照及输入分包。
- Play Mode 房间场景：通过九英雄模型包裹和截图、满血满墨无保护救起、攻击不破泡、重复 F、隔墙拒绝、敌方处决、归属计分、慢移/落地反弹、纯涂墨无即时伤害和正常复活。真实地图固定更新中完整等待十秒到期，再等待三秒复活通过；竞争请求只结算一次、比赛结束冻结、回房清理通过。
- 三个独立 Windows 进程直连：房主与非房主 F 救援、非房主泡泡移动、处决、超时复活、中途加入恢复，以及三端涂墨归属哈希一致通过。
- 延迟/丢包复测：每方向 60 毫秒延迟、±15 毫秒抖动、3% 丢包配置，代理实际转发 3208 包、丢弃 119 包。三进程全部通过，运行时无错误，最终涂墨归属哈希一致。结果见 `Reports/RescueBubble/Network-impaired-verified`；独立进程共享同一台电脑，不代表物理局域网或目标设备验收。
- 额外配置回归发现旧测试 `GameplayConfigTests.GeneratedDefaultsResolveFourTablesAndBallisticValues` 仍断言英雄 1 射速为 15，现有武器资产为 10；本次没有修改该武器资产或掩盖断言。

证据位于 `Reports/RescueBubble`：`editmode.xml`、`playmode.xml`、`hero-envelopes.csv`、`hero-*.png`、`fixed-expiry.csv` 及各联机目录。联机测试以 `-rescueRole host|client|late` 显式启用，正常游戏不运行。
