# 正式喷墨资源与权威弹道

本次以本机参考工程的当前工作副本为来源，包括其尚未提交的 Unity 6 / URP 17 适配。`reference-assets.json` 记录源提交、资源相对路径、原 GUID 和原文件 SHA-256；运行时代码不访问参考目录。

## 参考实现

- 参考有效场景为 `MixAndJam`。可见粒子每 0.03 秒发射两个；碰撞粒子每秒 40 个，并按移动距离每米追加 10 个。二者初速均为 20–25 米/秒，重力倍率为 2（实际加速度 19.62）。可见粒子寿命 1 秒，碰撞粒子寿命 0.5 秒。速度限制模块未启用。
- 参考通过粒子碰撞调用 TNTC 绘制器；命中点与球形笔刷在模型 UV 空间写入纹理，扩展 UV 岛以避免接缝。有效半径 0.2–1.5 米、硬度 0.01、强度 1。
- 屏幕空间 Metaballs 渲染先处理粒子深度与遮挡，再执行三次模糊和合成。原粒子回调没有联机权威或伤害规则。
- Jammo 使用 CharacterController；Animator 不开 Root Motion。持枪横移由瞄准待机和前后左右四段跑步动画二维混合形成斜向。场景内四组 Rig 提供胸部、头部、脊柱和双手约束，Splattershot 位于右手骨骼下。
- 实际提取保留 32 个 Renderer 和四组 Rig。源场景引用的 Avatar GUID 在参考工作副本中缺失，因此为 `jammo_mixamo_rig` 重建 Generic Avatar；跳跃/落地曲线从 `Armature.001` 重定向到同一骨架路径。

## 本工程运行链路

Boot → Addressables → 五张 Luban 表与校验 → 配置签名 → 玩法场景与网络 Prefab → NGO 房主模拟。

角色只发送输入。房主每个网络 Tick 驱动移动和发射累积器，再以 120 Hz 子步处理墨弹；每段轨迹进行球形扫掠，最近有效碰撞只结算一次。辅助瞄准射线不产生伤害。墨弹初速随机值和涂色半径由房主确定。

每秒 40 颗权威墨弹，每颗伤害 3.75、耗墨 0.3，理论持续伤害 150/秒、耗墨 12/秒。人物始终朝瞄准方向，客户端根据服务器时间显示弹道。友方角色阻挡墨弹，默认无友伤。死亡前已发射的墨弹继续飞行，回合重置和结算清除在途墨弹。

每颗权威墨弹默认显示两个视觉粒子，移动时每米追加十个视觉粒子，不增加耗墨、伤害或涂色。保留参考三次屏幕模糊、深度遮挡和 Alpha 合成；移除固定红色材质乘色及 RGB 阈值变色，保持橙蓝队色。命中特效根粒子设为 0.5 米，子发射器由粒子事件触发，避免直接播放整个层级导致额外的大块溅射。

## 表面与网络

竞技场地面、边界墙和掩体拥有稳定 SurfaceId。只有地面正面计分；掩体投影从总面积排除，掩体顶面不计分。绘制 UV1 为独立不重叠展开，原 UV0 继续用于基础材质。

PaintStamp 同时驱动房主地面归属和各端表面纹理。共同笔刷阈值为 0.5；绘制限制在命中的连通平面，避免薄墙背面串色。当前范围是正式竞技场的静态凸面网格；任意凹面和动态涂色物体需要额外的面连接数据。

参考表面 Shader Graph 的两处 Mask 采样均改为 UV1；只修改其中一处会出现归属已经变化、表面却看不见墨迹的问题。基础颜色与法线仍使用原 UV0。

地面网格为 256×256（0.125 米），不使用长度受限的逐格 NetworkList。增量按批次发送有序 PaintStamp。中途加入通过分块压缩快照恢复地面归属及全部已涂表面纹理，再应用检查点后的有序事件。

图形房主在一个事件序号边界复制 RT 并异步读回；压缩在工作线程执行。每 512 次涂色滚动检查点，缩短晚加入所需历史；块校验失败可重传。图形检查点不能用无图形启动的结果替代验收。

地面纹理为 1024²，其他表面 512²；按分辨率共享中间绘制纹理。所有纹理、表现池和加载句柄在卸载时释放。全局涂色 RT 预算为 128 MiB。

## 美术绑定与制作入口

正式资源放在 GameResource 的 Characters/Jammo、Weapons/Splattershot、Effects/Ink、Environment/Ink。模型、动画、Avatar、Rig、握持和粒子结构在 Prefab 内管理；玩法数值在 Excel 管理。

首次导入工具读取源资源，Unity 菜单“喷墨对战/内容/安装正式喷墨资源”从临时场景提取完整角色和粒子、建立正式 Prefab 并升级竞技场。安装工具是迁移入口，不是日常构建流程。

日常使用“喷墨对战/构建/Windows 正式资源版本”，只校验并构建已有资源，不重建角色或地图。入口仍为 Boot，原 Prototype/Arena、Prototype/Player、Prototype/Match 地址保留。

校验记录见 `Validation.md`。静态检查、Unity 导入编译、图形运行、本机多进程与实体双机验收分别记录。
